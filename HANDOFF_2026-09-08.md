# VYNE Platform — Handoff Notes (2026-09-08)

Current deployed version: **5.34.6** (production, Cloud Run `vyne-api` + Firebase Hosting)

## Fixed and live in 5.34.6
- **Empty-body 500 on `/api/voice/live-session`** — Fastify's default JSON parser
  threw "Unsupported Media Type" on a zero-length application/json body, surfacing
  as 500 internal_error and killing the realtime voice session. Fixed with a
  scoped empty-body-tolerant JSON parser on the voice/LLM route scope in
  `backend/src/server.ts`.
- **Pause not going inert** — `frontend/vyne-live.js`: a paused live session now
  discards the whole inbound turn (audio, text, turnComplete), and Pause flushes
  playback so nothing keeps talking.
- **Add-consultant "invalid_input"** — `backend/src/routes/assignments.ts` now
  returns a specific field message (e.g. "Initial password: must be at least 10
  characters") instead of a bare invalid_input.

## STILL OPEN (diagnosed, not fixed) — interview restart / voice
1. **Restart 429** — On restarting an interview, `POST /api/voice/live-session`
   returns 429 too_many_live_sessions because the prior session's reservation
   isn't released (concurrency guard: 3 sessions / 10-min window,
   `MAX_CONCURRENT_SESSIONS_PER_USER`, `OPEN_SESSION_WINDOW_SECONDS`). Result:
   falls back to robotic TTS instead of the Jack Smith / live voice.
2. **Two pause buttons** — the gold banner button (`vyne-pause-btn` in
   interview_agent.html) only stops `recognition` + `currentAudio`; it does NOT
   call LIVE.setMuted/stop. The live-path pause (separate control) does. Which
   one works depends on which audio path you're on.
3. **Overlapping voices** — `interview_agent.html` runs the Web Speech
   `recognition` object AND the live session; on restart they can both be active,
   producing two voices. Likely fix: when live is active, disable recognition
   entirely and route the banner Pause to LIVE.

Fix touches: frontend/interview_agent.html, frontend/vyne-live-interview.js,
frontend/vyne-live.js. Needs all three open together — real multi-file work.

## CRITICAL ENV CAVEAT (not in repo — lives only in Cloud Run)
- `GEMINI_LIVE_MODEL` MUST be `models/gemini-2.5-flash-native-audio-latest`.
  The value `gemini-live-2.5-flash-preview` MINTS a token fine but the live
  WebSocket rejects it with close code 1008 ("not supported for
  bidiGenerateContent") → robotic fallback. A fresh deploy does NOT restore this
  env var automatically. Verify after any Cloud Run redeploy.
